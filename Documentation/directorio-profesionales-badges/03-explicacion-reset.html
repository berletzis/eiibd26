¿Qué hace el reset?

El reset revierte el estado administrativo de un profesional al estado inicial "limpio", como si nunca hubiera pasado por el proceso de verificación o reclamación, sin eliminar datos históricos valiosos.

Casos de uso legítimos:
  • Un médico reclamó el perfil pero resultó ser suplantación de identidad.
  • Se verificó una cédula por error y hay que revertir la verificación.
  • Un registro duplicado: se quiere deslindar el usuario vinculado antes de fusionar.
  • Testing / QA en entorno de producción (usar con extremo cuidado).

Cálculo de NivelConfianza post-reset

Sin claim ni cédula verificada, el NivelConfianza depende solo de las confirmaciones activas:

DECLARE @TotalConfs INT;
SELECT @TotalConfs = COUNT(*)
FROM ConfirmacionComunitaria
WHERE MedicoDirectorioId = @MedicoId AND Eliminado = 0;

SET @NuevoNivel =
    CASE
        WHEN @TotalConfs >= 5 THEN 2  -- Reconocido
        WHEN @TotalConfs >= 3 THEN 1  -- Confirmado
        ELSE 0                         -- Identificado
    END;

Esto respeta la fórmula canónica de CalcularNivelVerificacion sin el factor de cédula verificada ni perfil reclamado, que se eliminaron en el reset.

Si el médico tenía CedulaVerificada = true con menos de 5 confirmaciones y nivel 2 por esa razón, post-reset podría bajar a nivel 0 o 1. Eso es correcto: sin cédula verificada el nivel debe reflejar solo la evidencia comunitaria.

Pasos de ejecución seguros

0
Verificar estado actual (SELECT de auditoría)
Ejecutar el PASO 0 del script para confirmar que el @MedicoId correcto. Documentar el estado antes del cambio (screenshot o copiar resultado).
1
Ver badges actuales (PASO 1)
Confirmar qué badges serán eliminados. Si hay badges que deben preservarse (p.ej. creador_contenido otorgado manualmente por mérito propio), el reset actual los eliminaría todos — en ese caso considerar eliminar solo los específicos.
2
Ejecutar el bloque RESET dentro de transacción
Copiar el bloque BEGIN TRANSACTION / COMMIT y ejecutar. La transacción garantiza que si falla cualquier paso, nada se aplica parcialmente.
3
Verificar estado post-reset (PASO 2)
El SELECT final muestra: todos los campos limpiados, badges_restantes = 0, confs_intactas = N (sin cambio).
4
(Opcional) Reset extendido — desvincular perfil extendido
Si se requiere desvincular el UserId de MedicoPerfilExtendido, descomentar el bloque opcional. Solo hacer esto si hay certeza de que el usuario vinculado no es el médico legítimo.

Advertencias importantes

⚠ Eliminar badges es destructivo e irreversible en el esquema actual.
Hasta que no se implemente la trazabilidad de revocaciones (FASE 3), no hay forma de saber después del reset cuándo/quién/por qué se eliminaron los badges. Documentar la operación manualmente (quién ejecutó el reset, fecha, motivo).
El reset afecta lo que ve el médico en su dashboard.
Si el médico tiene cuenta activa con rol Medico, al hacer reset ya no verá sus badges ni permisos de nivel. Considerar si se debe notificar al médico.
El reset NO revoca el rol Medico de AspNetRoles.
Si el usuario fraudulento tiene el rol Medico asignado, ese rol sigue activo después del reset. Revocar el rol es una operación separada vía el panel de administración de usuarios.
