FASE 7 — Escenarios de Validación con Playwright

Proyecto EIIBD · Directorio de Profesionales · Generado 2026-05-27

Contexto

Estos escenarios cubren los flujos críticos del sistema de badges y estados, con énfasis en las discrepancias identificadas en FASE 1. Se ejecutan con Playwright MCP (mcp__playwright__*) contra el servidor local o de staging.

Precondición: servidor corriendo en https://localhost:5001. Credenciales de admin disponibles.

Escenarios de validación

SC-01: Verificar cédula desde botón rápido → badge verificado se otorga Cubre D-01

Precondición: Profesional con cédula no verificada. Sin badge verificado.

  1. Navegar a /Identity/Admin/DirectorioMedicos
  2. Localizar profesional en el grid (buscar por nombre)
  3. Hacer clic en el botón "Verificar cédula" de la fila del grid
  4. Esperar respuesta JSON { success: true }
  5. Abrir panel de edición del mismo profesional
  6. Ir a sección 7 (Badges)
✓ Badge "verificado" aparece como obtenido en la sección de badges
✓ FechaObtenido coincide con la hora de la acción
✓ OtorgadoPor = "admin"
SC-02: Verificar cédula desde panel de edición → badge verificado se otorga Flujo base

Precondición: Profesional con cédula no verificada.

  1. Abrir panel de edición del profesional
  2. Activar switch "Cédula verificada" en sección 4
  3. Hacer clic en "Guardar cambios"
  4. Cerrar y reabrir panel
✓ Badge "verificado" aparece como obtenido
✓ Sección 4 muestra FechaCedulaVerificada
SC-03: Desverificar cédula → badge verificado se revoca Flujo base

Precondición: Profesional con badge verificado obtenido.

  1. Abrir panel de edición
  2. Desactivar switch "Cédula verificada"
  3. Guardar cambios
  4. Reabrir panel
✓ Badge "verificado" aparece como NO obtenido
✓ Historial muestra evento "revocado" con actor "admin" (tras FASE 3)
SC-04: Aprobar claim → badge perfil_reclamado se otorga, nivel = 3 Cubre D-02

Precondición: Profesional con solicitud de claim pendiente (EstatusReclamacion = EnProceso). Sin badge perfil_reclamado.

  1. Filtrar grid por "Con solicitud de claim"
  2. Abrir panel del profesional
  3. Hacer clic en "Aprobar claim" (sección 5)
  4. Reabrir panel
✓ Badge perfil_reclamado aparece como obtenido
✓ EstatusReclamacion = "Reclamado"
✓ NivelConfianza = 3 (Establecido)
✓ Grid muestra icono de "Reclamado" en la fila
SC-05: Revocar badge manual → badge desaparece, historial registra evento Flujo base + FASE 3

Precondición: Profesional con badge creador_contenido o cualquier badge obtenido.

  1. Abrir panel de edición del profesional
  2. En sección 7, hacer clic en "Revocar" del badge
  3. Confirmar en el diálogo de confirmación
  4. Reabrir panel
✓ Badge aparece como NO obtenido
✓ Historial muestra "revocado" con actor "admin" y fecha (tras FASE 3)
✓ Sin error 500 ni mensaje de error en pantalla
SC-06: Evaluar badges automáticos → badges correctos se otorgan Flujo base

Precondición: Profesional con ≥5 confirmaciones y usuario vinculado con ≥3 respuestas en Q&A.

  1. Abrir panel del profesional
  2. Hacer clic en "Evaluar badges automáticos"
  3. Reabrir panel
✓ Badge activo_comunidad aparece obtenido (≥5 confirmaciones)
✓ Badge participante_qa aparece obtenido (≥3 respuestas)
✓ Badge verificado NO cambia (no lo evalúa EvaluarBadgesAutomaticosAsync)
SC-07: Paciente ve estado correcto en "Mis aportaciones" Flujo base

Precondición: Paciente autenticado con propuestas en distintos estados.

  1. Iniciar sesión como paciente
  2. Navegar a /DirectorioMedicos
  3. Verificar sección "Mis aportaciones"
✓ Propuesta Propuesto → badge "En revisión" (bg-warning)
✓ Propuesta Publicado → badge "Publicado en el directorio" (bg-primary)
✓ Propuesta Reclamado → badge "Reclamado por el profesional" (bg-info)
✓ Propuesta CedulaVerificada → badge "Cédula verificada" (bg-success)
✓ Propuestas Publicado/Reclamado tienen enlace "Ver perfil"
SC-08: Grid admin — switch "Mostrar eliminados" funciona correctamente BUG-1 (ya corregido)

Precondición: Existen profesionales activos Y profesionales soft-deleted.

  1. Navegar al grid admin
  2. Verificar que con switch OFF se muestran solo activos
  3. Activar switch "Mostrar eliminados"
  4. Verificar que ahora se muestran solo los eliminados
✓ Con switch OFF: todos los registros tienen eliminado = false
✓ Con switch ON: todos los registros tienen eliminado = true
✓ No hay mezcla de registros activos y eliminados en ningún estado del switch
SC-09: Recalcular nivel desde panel admin → nivel refleja confirmaciones actuales FASE 5 + FASE 6

Precondición: Profesional con NivelConfianza desincronizado (ej. manualmente seteado a un valor incorrecto).

  1. Abrir panel del profesional
  2. Hacer clic en "Recalcular nivel"
  3. Verificar respuesta y refrescar panel
✓ NivelConfianza actualizado según fórmula canónica
✓ Toast muestra el nuevo nivel
