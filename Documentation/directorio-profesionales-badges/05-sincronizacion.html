FASE 5 — RecalcularEstadoProfesional Canónico

Proyecto EIIBD · Directorio de Profesionales · Generado 2026-05-27

Problema

La lógica de recalcular el nivel de confianza de un profesional existe en dos lugares distintos del código (discrepancia D-03 de FASE 1):

MétodoArchivoLlamado desde
RecalcularNivelConfianzaAsync(int medicoId) MedicoDirectorioService ConfirmarAtencionAsync
RecalcularNivelAsync(MedicoDirectorio, int) (privado) Admin/DirectorioMedicos/Index.cshtml.cs OnPostVerificarCedulaAsync, OnPostEditarAsync

Adicionalmente, OnPostAprobarClaimAsync hace un hardcode directo: medico.NivelConfianza = NivelConfianzaEnum.Establecido, saltándose la fórmula por completo.

Solución — Punto único de recálculo

El método canónico ya existe en MedicoDirectorioService.RecalcularNivelConfianzaAsync. La corrección es simple: todos los callers deben usar ese único método. No hay que crear nada nuevo.

Plan de migración

Caller actualCambio requerido
OnPostVerificarCedulaAsync → RecalcularNivelAsync(m, id) Delegar a await _service.RecalcularNivelConfianzaAsync(id)
OnPostEditarAsync → RecalcularNivelAsync(medico, id) Delegar a await _service.RecalcularNivelConfianzaAsync(id)
OnPostAprobarClaimAsync → hardcode NivelConfianza = Establecido Reemplazar hardcode con await _service.RecalcularNivelConfianzaAsync(id) después de guardar el claim
Nota sobre OnPostAprobarClaimAsync: El hardcode a Establecido (3) es funcionalmente correcto para el caso normal (claim aprobado implica perfil reclamado, que vale nivel 3). Sin embargo, delegar al servicio canónico es más seguro: si la fórmula cambia (p.ej. se añade un nivel 4), el claim seguirá calculando el valor correcto.

Cambio 1 — Inyectar servicio en el admin

El admin handler no tiene acceso a IMedicoDirectorioService. Debe inyectarse:

    _service = service;  // NUEVO

Cambio 5 — Eliminar método privado RecalcularNivelAsync

Una vez que todos los callers deleguen al servicio, el método privado puede eliminarse del admin handler:

// ELIMINAR este método de Admin/Index.cshtml.cs:
private async Task RecalcularNivelAsync(MedicoDirectorio medico, int id)
{
    var total    = await _db.ConfirmacionesComunitarias.CountAsync(c => c.MedicoDirectorioId == id && !c.Eliminado);
    var tieneEII = total > 0;
    var nivel = medico.PerfilReclamado ? 3
        : (medico.CedulaVerificada || total >= 5) ? 2
        : (total >= 3 && tieneEII) ? 1
        : 0;
    medico.NivelConfianza = (NivelConfianzaEnum)nivel;
    await _db.SaveChangesAsync();
}

Cambio 6 — OnPostRevocarBadgeAsync (FIX D-04)

El admin handler duplica la lógica de _badgeService.RevocarBadgeAsync. Simplificar:

// ANTES (duplicado)
public async Task<IActionResult> OnPostRevocarBadgeAsync(int medicoId, string codigo)
{
    var badge = await _db.MedicosBadge.AsNoTracking()
        .FirstOrDefaultAsync(b => b.Codigo == codigo);
    if (badge is null) return new JsonResult(new { success = false });
    var entry = await _db.MedicosPerfilBadge
        .FirstOrDefaultAsync(pb => pb.MedicoId == medicoId && pb.BadgeId == badge.Id);
    if (entry is null) return new JsonResult(new { success = false });
    _db.MedicosPerfilBadge.Remove(entry);
    await _db.SaveChangesAsync();
    return new JsonResult(new { success = true });
}

// DESPUÉS — delega al servicio (que además registrará en historial tras FASE 3)
public async Task<IActionResult> OnPostRevocarBadgeAsync(int medicoId, string codigo)
{
    var result = await _badgeService.RevocarBadgeAsync(medicoId, codigo, "admin");
    return new JsonResult(new { success = result });
}
