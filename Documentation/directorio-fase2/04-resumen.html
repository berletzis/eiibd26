Cambios de comportamiento notables

Dashboard — Áreas EII por confirmación: La vista mostraba tags como "CUCI", "Crohn", "Biológicos" por cada confirmación, extraídos de los campos booleanos del modelo antiguo. En el nuevo modelo esas etiquetas siempre son vacías (todos los Exp* = false), porque ConfirmacionComunitaria no almacena granularidad por área EII. El contador total y los nombres de pacientes siguen funcionando correctamente.
Admin — expContadores: El panel de detalle del médico mostraba conteos por área (CUCI: 3, Crohn: 2, etc.). Ahora muestra todos en 0. La estructura JSON es idéntica para no romper el frontend JS. La lista de confirmadores muestra el TipoConfirmacion.Nombre en lugar de las etiquetas de área.
Tabla DirectorioMedicoConfirmacion: El DbSet y el modelo se mantienen en la aplicación. La tabla en BD no se elimina. Contiene datos históricos de confirmaciones previas a la migración. Si en el futuro se decide eliminar, requiere script SQL idempotente en SQL/.
