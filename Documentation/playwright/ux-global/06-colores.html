Problema central: 3 sistemas de color coexisten

COL-01 CRÍTICO — Triple sistema de tokens de color sin unificación
El sitio tiene tres familias de variables CSS completamente distintas que no se referencian entre sí:
• Bootstrap nativo: --bs-primary: #0d6efd (azul) — usado por .btn-primary, .btn-danger, etc.
• Prefijo --se-*: sistema propio inicial (backgrounds, links, textos). --se-primary: #f7f9fd (blanco azulado — no es un "primario")
• Prefijo --crm-*: sistema más nuevo. --crm-accent: #7c3aed (púrpura brillante)
• Variables globales sin prefijo: --brand-color: #6a4e7a, --text-color: #1f2b2f, etc.

El color de marca real #6a4e7a NO coincide ni con el acento CRM #7c3aed ni con el primary Bootstrap #0d6efd. Los botones principales del sitio son azul Bootstrap, no el color de marca.

COL-02 — Tres colores de texto "muted" diferentes
--muted-color: #546a70, --crm-muted: #6b7280, y el body text en rgba(33,37,41,0.75) son tres grises distintos. Visualmente similares pero técnicamente inconsistentes. Al usar zoom o modo oscuro las diferencias se amplifican.

COL-03 CRÍTICO — 4 variantes de color "danger/error"
#dc3545 (Bootstrap) · #b94a42 (custom) · #c92a2a (CRM) · #dd3333 (SE). Cuando el usuario ve un mensaje de error o botón destructivo, el color varía según qué módulo lo generó. Rompe la consistencia semántica del color rojo = peligro.
COL-04 — 2 variantes de warning
#ffc107 (Bootstrap amarillo) vs #c38f3b (custom ámbar). El warning custom es más oscuro y serio. Sin estándar único.
