PROBLEMA CRÍTICO: Dos sistemas de fuente coexisten
• Bootstrap carga system-ui, -apple-system, "Segoe UI", Roboto... como --bs-body-font-family
• El CSS custom define --ui-font: "Inter", system-ui... con Inter como primera opción
Resultado: en navegadores donde Inter NO está instalada, el rendering cambia. La fuente real en producción depende del dispositivo del usuario.

Problemas detectados

TIP-01 — H1 con font-weight: 300 (Light)
El H1 principal del sitio usa peso 300, que da apariencia frágil. Para contenido médico donde la confianza es crítica, los títulos principales deben usar 600–700. El H1 del hero en /Home ("Vivir con EII...") se ve elegante pero pierde autoridad visual.
TIP-02 — Texto de cuerpo en rgba(33,37,41,0.75) — opacidad 75%
El texto principal de párrafos usa 75% de opacidad en lugar de color sólido. En fondos no-blancos esto reduce el contraste de forma impredecible. El ratio de contraste exacto depende del fondo. Para texto médico, usar color sólido #495057 o #343a40.
TIP-03 — Cuerpo a 14.4px (0.9rem)
El texto de párrafos está escalado al 90% del base. Para una plataforma de salud donde pacientes leen información médica extensa, el mínimo recomendado es 16px. Pacientes adultos o con problemas de visión (frecuente en EII sistémica) se ven afectados.
TIP-04 — .crm-btn-primary con font-weight: 100 (UltraThin)
El botón "+" redondo del dashboard (agregar ánimo) usa peso 100. En pantallas de baja resolución o modo oscuro el ícono + es prácticamente invisible. Error de estilo severo.
TIP-05 ✓ — Input a 16px
Los inputs usan 16px — esto evita el zoom automático en iOS. Correcto.
TIP-06 ✓ — Line-height cuerpo 1.5
El interlineado de párrafos en 1.5 (21.6px) es el valor WCAG recomendado. Correcto.
