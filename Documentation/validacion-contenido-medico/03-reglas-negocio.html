03 — Reglas de Negocio

Unicidad, auto-validación, estados y moderación.

1. Una sola validación por médico por perfil

Regla fundamental: Un médico puede tener como máximo UN registro de validación de tipo PerfilMedico para su propio perfil. Si intenta validar de nuevo, el sistema actualiza el registro existente (Upsert) en lugar de crear uno nuevo.

Esta unicidad está garantizada a dos niveles:

  1. Índice único en BD: (TipoContenido, ContenidoId, UsuarioMedicoId) — previene duplicados aunque haya un bug en el código.
  2. Lógica en servicio: UpsertAsync hace FirstOrDefaultAsync antes de decidir si inserta o actualiza.

2. Auto-validación: el médico certifica su propio perfil

  • Solo el médico dueño del perfil puede crear o actualizar su validación.
  • El sistema verifica que UsuarioMedicoId == User.GetUserId() antes de aceptar el POST.
  • Un médico no puede validar el perfil de otro médico con este mecanismo.
  • El handler en PerfilMedico.cshtml.cs obtiene el MedicoDirectorioId ligado al usuario autenticado y lo usa como ContenidoId.

3. Estado por defecto: Validado

Cuando el médico hace submit por primera vez (o actualiza), el estado siempre se establece en EstadoValidacion.Validado (1). El médico no puede elegir el estado — es automático.

El indicador "Perfil validado por el profesional" aparece en la página pública inmediatamente después de la auto-certificación, sin necesidad de aprobación admin previa.

4. Sin eliminación

No existe endpoint para que el médico elimine su propia validación. Los registros son permanentes. Solo el admin puede cambiar el estado, pero no puede borrar el registro de BD.

Justificación: preservación de auditoría. Si el admin pone en revisión o oculta la validación, queda trazabilidad de quién la moderó, cuándo y por qué.

5. Moderación por admin: cambio de estado

El admin puede cambiar el estado de cualquier validación de tipo PerfilMedico a:

EstadoValorEfecto en página pública
Validado 1 Badge visible — "Perfil validado por el profesional"
EnRevision 2 Badge oculto — el registro existe pero no se muestra
Oculto 3 Badge oculto — ocultamiento permanente hasta que admin revierta

Cuando el admin cambia el estado se registran: ModeradoPorId, FechaModeracion, y opcionalmente NotaModeracion.

6. Visibilidad en página pública

La query en Detalle.cshtml.cs es:

var validacion = await _context.ValidacionesContenidoProfesional
    .FirstOrDefaultAsync(v =>
        v.TipoContenido == TipoContenidoValidado.PerfilMedico
        && v.ContenidoId == medicoId
        && v.Estado == EstadoValidacion.Validado);

ViewData["PerfilValidado"] = validacion != null;

Si Estado != Validado → ViewData["PerfilValidado"] = false → el badge no se renderiza.

7. Actualización del indicador en PerfilMedico

Cuando el médico regresa a /Identity/Account/Manage/PerfilMedico, el page model carga el registro existente y muestra:

  • Si no existe validación: botón "Validar mi perfil"
  • Si existe con estado Validado: badge verde "Validado" + botón "Actualizar validación"
  • Si existe con estado EnRevision u Oculto: aviso "Validación en revisión por el equipo"
