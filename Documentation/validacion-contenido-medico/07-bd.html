07 — Base de Datos

Sin nuevas tablas. TipoContenidoValidado.PerfilMedico=3 en tabla existente.

1. No se crea nueva tabla

Cero nuevas tablas. La feature reutiliza la tabla ValidacionesContenidoProfesional ya existente. Solo se agrega el valor PerfilMedico = 3 al enum TipoContenidoValidado, que se almacena como TINYINT en la columna TipoContenido.

2. Estructura de la tabla existente

CREATE TABLE dbo.ValidacionesContenidoProfesional (
    Id               INT IDENTITY(1,1) NOT NULL PRIMARY KEY,
    TipoContenido    TINYINT NOT NULL,          -- 1=Termino, 2=Articulo, 3=PerfilMedico
    ContenidoId      INT NOT NULL,
    UsuarioMedicoId  NVARCHAR(450) NOT NULL,    -- FK → AspNetUsers
    Comentario       NVARCHAR(800) NULL,
    Estado           TINYINT NOT NULL DEFAULT 1, -- 1=Validado, 2=EnRevision, 3=Oculto
    CreadoEn         DATETIME2 NOT NULL,
    ActualizadoEn    DATETIME2 NOT NULL,
    ModeradoPorId    NVARCHAR(450) NULL,        -- FK → AspNetUsers (admin)
    FechaModeracion  DATETIME2 NULL,
    NotaModeracion   NVARCHAR(500) NULL
);

3. Índice único existente

-- Previene que el mismo médico valide el mismo contenido más de una vez
CREATE UNIQUE INDEX IX_ValidacionesContenido_Tipo_Contenido_Usuario
    ON dbo.ValidacionesContenidoProfesional (TipoContenido, ContenidoId, UsuarioMedicoId);

Este índice ya cubre el caso PerfilMedico (3) sin modificación. Un médico con UserId = 'abc' solo puede tener UN registro donde TipoContenido = 3 y ContenidoId = <su MedicoDirectorio.Id>.

4. Query de verificación: datos de PerfilMedico en BD

-- Ver validaciones de perfil médico activas
SELECT v.Id, v.ContenidoId, v.UsuarioMedicoId,
       v.Estado, v.CreadoEn, v.ActualizadoEn,
       v.ModeradoPorId, v.NotaModeracion
FROM dbo.ValidacionesContenidoProfesional v
WHERE v.TipoContenido = 3   -- PerfilMedico
ORDER BY v.CreadoEn DESC;

5. Relación con MedicosDirectorio

No hay FK formal entre ValidacionesContenidoProfesional.ContenidoId y MedicosDirectorio.Id. Esta es la misma decisión de diseño usada para Termino y Articulo: la FK es semántica (por convención de tipo), no estructural en la BD.

Esto evita complejidad de FK multi-tabla y mantiene la tabla genérica para todos los tipos de contenido.

6. Impacto de agregar TipoContenido = 3

AspectoImpacto
Tabla en SQL ServerNinguno — la columna TINYINT ya acepta el valor 3
Índice únicoNinguno — ya cubre el caso con el composite key
EF Core DbSetNinguno — el DbSet ya existe
Enum C#Agregar PerfilMedico = 3 al archivo del enum
Registros existentesNinguno — no se tocan los Termino y Articulo existentes

7. Script de verificación post-feature

-- Confirmar que el índice único funciona (intentar insertar duplicado debe fallar):
SELECT TipoContenido, ContenidoId, UsuarioMedicoId, COUNT(*) AS Total
FROM dbo.ValidacionesContenidoProfesional
WHERE TipoContenido = 3
GROUP BY TipoContenido, ContenidoId, UsuarioMedicoId
HAVING COUNT(*) > 1;
-- Debe retornar 0 filas.

-- Conteo de validaciones de perfil por estado:
SELECT Estado, COUNT(*) AS Total
FROM dbo.ValidacionesContenidoProfesional
WHERE TipoContenido = 3
GROUP BY Estado;
