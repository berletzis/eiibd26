FASE 3 — Fix BUG-1: Soft Delete en Admin Grid · EIIBD.com · Mayo 2026

Diagnóstico definitivo del BUG-1

Síntoma: Admin activa switch "Eliminados" → Los profesionales eliminados NO aparecen en el grid.
Causa raíz: La query en OnGetGridDataAsync dice: 
var query = _db.MedicosDirectorio.AsNoTracking()
    .Where(m => mostrarEliminados || !m.Eliminado);

Esta condición es lógicamente correcta en teoría. Sin embargo, si ApplicationDbContext tiene un Global Query Filter como:

builder.Entity<MedicoDirectorio>().HasQueryFilter(m => !m.Eliminado);

ese filtro se aplica automáticamente a toda query sobre esa entidad, incluso cuando el código C# no lo incluye. El .Where(m => mostrarEliminados || !m.Eliminado) no cancela el Global Query Filter — solo añade otra condición encima. El resultado: !m.Eliminado AND (mostrarEliminados OR !m.Eliminado) — siempre filtra eliminados.

Paso 1: Verificar si existe el Global Query Filter

Buscar en Data/ApplicationDbContext.cs el método OnModelCreating para MedicosDirectorio:

// Buscar esto:
builder.Entity<MedicoDirectorio>()
    .HasQueryFilter(m => !m.Eliminado);  // ← si existe, es la causa raíz
Nota: El Global Query Filter existe en Contenidos (confirmado por el código de Contenidos.cshtml.cs que usa IgnoreQueryFilters() cuando mostrarEliminados=true). Es muy probable que también exista para MedicosDirectorio o que el handler no esté usando el parámetro correctamente desde DataTables GET.

Paso 2: Causa alternativa — parámetro no llega como bool

DataTables envía el parámetro vía GET como string. El model binder de ASP.NET Core convierte "true" a true para parámetros bool en handlers GET. Pero hay un caso edge: si el JS envía mostrarEliminados=false como string vacío o no lo envía cuando está unchecked, el default false prevalece correctamente. Verificar que el JS envía el valor en ambos estados:

// En Index.cshtml — verificar que data function envía el bool
ajax: {
    url: '@Url.Page(null, "GridData")', type: 'GET',
    data: d => {
        d.mostrarEliminados = $('#switchEliminados').is(':checked');  // ← envía true/false
        d.filtroVerificado  = $('#filtroVerificado').val();
    }
}

Fix completo — OnGetGridDataAsync

Solución: Usar IgnoreQueryFilters() cuando mostrarEliminados=true y aplicar el filtro manualmente, exactamente igual que hace Contenidos.cshtml.cs. 
// Areas/Identity/Pages/Admin/DirectorioMedicos/Index.cshtml.cs

public async Task<IActionResult> OnGetGridDataAsync(
    bool mostrarEliminados = false, string? filtroVerificado = null)
{
    var draw   = int.TryParse(Request.Query["draw"],   out var d) ? d : 1;
    var start  = int.TryParse(Request.Query["start"],  out var s) ? s : 0;
    var length = int.TryParse(Request.Query["length"], out var l) ? l : 25;
    var search = Request.Query["search[value]"].ToString();

    // ── FIX BUG-1: respetar Global Query Filter ──────────────────────
    IQueryable<MedicoDirectorio> query = mostrarEliminados
        ? _db.MedicosDirectorio.IgnoreQueryFilters().AsNoTracking()   // ← muestra TODOS (incl. eliminados)
        : _db.MedicosDirectorio.AsNoTracking();                        // ← respeta el filter (solo activos)

    // Cuando mostramos eliminados, queremos SOLO los eliminados (no mezclar)
    // Si el admin activa el switch, espera ver ÚNICAMENTE los eliminados.
    // Si quiere ver todos, necesita un tercer modo — por ahora: switch ON = solo eliminados
    if (mostrarEliminados)
        query = query.Where(m => m.Eliminado);
    // else: el Global Query Filter ya filtra !m.Eliminado automáticamente

    // ─────────────────────────────────────────────────────────────────
    if (!string.IsNullOrWhiteSpace(search))
        query = query.Where(m =>
            m.NombreCompleto.Contains(search) ||
            (m.Especialidad != null && m.Especialidad.Contains(search)) ||
            (m.Estado       != null && m.Estado.Contains(search))       ||
            (m.Ciudad       != null && m.Ciudad.Contains(search)));

    if (filtroVerificado == "verificado")
        query = query.Where(m => m.EstatusValidacion == EstatusValidacionCedula.Validado);
    else if (filtroVerificado == "pendiente")
        query = query.Where(m => m.EstatusValidacion != EstatusValidacionCedula.Validado);
    else if (filtroVerificado == "claim")
        query = query.Where(m => m.EstatusReclamacion == EstatusReclamacion.EnProceso);

    var total = await query.CountAsync();

    var rows = await query
        .OrderByDescending(m => m.FechaCreacion)
        .Skip(start).Take(length)
        .Select(m => new
        {
            m.Id,
            m.NombreCompleto,
            Especialidad         = m.Especialidad ?? string.Empty,
            Estado               = m.Estado       ?? string.Empty,
            Ciudad               = m.Ciudad       ?? string.Empty,
            Ubicacion            = string.Join(", ", new[] { m.Ciudad, m.Estado }.Where(x => !string.IsNullOrEmpty(x))),
            verificado           = m.EstatusValidacion == EstatusValidacionCedula.Validado,
            solicitudClaim       = m.EstatusReclamacion == EstatusReclamacion.EnProceso,
            perfilReclamado      = m.EstatusReclamacion == EstatusReclamacion.Reclamado,
            totalConfirmaciones  = _db.ConfirmacionesComunitarias
                                     .Count(c => c.MedicoDirectorioId == m.Id && !c.Eliminado),
            tieneConfirmacionEII = _db.ConfirmacionesComunitarias
                                     .Any(c => c.MedicoDirectorioId == m.Id && !c.Eliminado),
            m.Eliminado,
            FechaCreacion        = m.FechaCreacion.ToString("dd/MM/yyyy")
        })
        .ToListAsync();

    return new JsonResult(new
    {
        draw,
        recordsTotal    = total,
        recordsFiltered = total,
        data            = rows
    });
}

Fix en el handler de Restaurar

OnPostRestaurarAsync — debe usar IgnoreQueryFilters

El handler de restaurar también puede fallar si usa la query normal, porque el registro eliminado no será encontrado:

public async Task<IActionResult> OnPostRestaurarAsync()
{
    if (!Request.HasFormContentType) return BadRequest();
    var id = int.Parse(Request.Form["id"]!);

    // ← CRÍTICO: usar IgnoreQueryFilters para encontrar el registro eliminado
    var m = await _db.MedicosDirectorio
        .IgnoreQueryFilters()
        .FirstOrDefaultAsync(x => x.Id == id);

    if (m is null) return new JsonResult(new { success = false, message = "Registro no encontrado." });
    if (!m.Eliminado) return new JsonResult(new { success = false, message = "El registro no está eliminado." });

    m.Eliminado         = false;
    m.FechaModificacion = DateTimeOffset.UtcNow;
    await _db.SaveChangesAsync();

    return new JsonResult(new { success = true });
}

Fix en el handler de Detalle (OnGetMedicoAsync)

OnGetMedicoAsync — abrir panel de un registro eliminado

Cuando el admin abre el panel de detalle de un registro eliminado (para restaurarlo), la query actual no lo encontrará:

// ANTES:
var m = await _db.MedicosDirectorio.FirstOrDefaultAsync(m => m.Id == id);

// DESPUÉS:
var m = await _db.MedicosDirectorio
    .IgnoreQueryFilters()        // ← encuentra registros eliminados también
    .FirstOrDefaultAsync(m => m.Id == id);

Verificación: ¿Existe el Global Query Filter?

Qué buscar en ApplicationDbContext.OnModelCreating

Si el Global Query Filter no existe para MedicosDirectorio, el fix del handler sigue siendo correcto (la condición mostrarEliminados ? IgnoreQueryFilters() : normal funciona en ambos casos). Si el filter sí existe, el fix es indispensable.

Buscar en Data/ApplicationDbContext.cs:

// ¿Existe algo así?
modelBuilder.Entity<MedicoDirectorio>()
    .HasQueryFilter(m => !m.Eliminado);
// o
modelBuilder.Entity<MedicoDirectorio>()
    .HasQueryFilter(m => m.Activo && !m.Eliminado);
Acción: Si no existe el Global Query Filter, el bug puede tener otra causa: posiblemente el parámetro mostrarEliminados no llega como true desde el JS. Verificar con las DevTools del navegador que la URL del DataTables incluya mostrarEliminados=true cuando el switch está activado.
