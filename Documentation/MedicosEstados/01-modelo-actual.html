6. Bugs Identificados — Causa Raíz

BUG-1 — Admin Grid: Eliminados no aparecen

El switch #switchEliminados en el frontend envía mostrarEliminados=true al handler OnGetGridDataAsync(bool mostrarEliminados). El código del handler luce correcto:

var query = _db.MedicosDirectorio.AsNoTracking()
    .Where(m => mostrarEliminados || !m.Eliminado);

Causa raíz probable: El parámetro booleano llega como string "true" desde la URL de DataTables (GET), pero el model binder de ASP.NET convierte "true" a true correctamente en teoría. Sin embargo, si hay un Global Query Filter en EF sobre MedicosDirectorio que siempre filtra !Eliminado, ese filtro PREVALECE aunque el código diga || !m.Eliminado. La query no usa IgnoreQueryFilters().

Acción requerida: Verificar ApplicationDbContext.OnModelCreating() — si hay un HasQueryFilter(m => !m.Eliminado) sobre MedicosDirectorio, el handler debe usar .IgnoreQueryFilters() cuando mostrarEliminados=true, igual que hace Contenidos.cshtml.cs.

BUG-2 — Paciente sigue viendo "pendiente" aunque la cédula haya sido verificada

En Pages/DirectorioMedicos/Index.cshtml.cs, el método GetMisPropuestasAsync() carga todos los médicos propuestos por el usuario sin importar su estado. La vista los muestra con badge fijo "En revisión".

Causa raíz: No existe un campo EstatusPropuesta ni un estado semántico que refleje "qué sabe el paciente". El estado administrativo (Activo, EstatusValidacion) existe, pero no se proyecta al paciente. El componente de "Mis propuestas" usa lógica hardcoded: si el profesional fue propuesto por el usuario, siempre muestra "pendiente".

Acción requerida: Crear lógica de derivación: si Activo=true && VisiblePublicamente=true → estado "Publicado"; si EstatusValidacion=Validado → "Cédula verificada"; si ninguno → "En revisión".

BUG-3 — Admin panel: dos verdades sobre "Verificado"

En el panel lateral del Admin, hay dos fuentes independientes que definen si un profesional está "verificado":

  • Arriba del panel: Checkbox ep_cedulaVerificada ← lee d.cedulaVerificada (from m.CedulaVerificada = EstatusValidacion == Validado)
  • Sección Badges: Badge verificado ← lee MedicoPerfilBadge donde Codigo="verificado"

Estas dos fuentes no se sincronizan automáticamente. El admin puede marcar la cédula como verificada SIN que se otorgue el badge "verificado", o viceversa.

Causa raíz: El badge "verificado" es manual (requiere que admin lo otorgue desde el panel de badges). El checkbox "Cédula verificada" actualiza solo EstatusValidacion. No hay un hook que los una.

Acción requerida: Cuando admin activa "Cédula verificada", debe dispararse automáticamente OtorgarBadgeAsync(id, "verificado", "admin"). Y viceversa: revocar badge al desmarcar.

8. Cambio Semántico — Directorio de Profesionales de la Salud

Alcance del cambio de nombre

El módulo pasa de llamarse "Directorio de Médicos" a "Directorio de Profesionales de la Salud". El sistema debe prepararse para:

  • Médicos (especialistas, gastroenterólogos)
  • Nutriólogos y Dietistas
  • Psicólogos
  • Otros profesionales vinculados a EII
