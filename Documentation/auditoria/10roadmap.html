Fase 4 — Largo plazo (6+ meses)

Mejoras arquitectónicas PWA completo Accesibilidad WCAG

Mejoras estratégicas de alto esfuerzo que transforman la arquitectura del sistema. Requieren planificación de sprints dedicados y revisión de requisitos.

4A · Arquitectura

  • Evaluar extracción de módulo de Directorio Médico como área separada con su propio contexto de BD (bounded context)
  • Implementar output caching para páginas públicas del directorio y glosario (ASP.NET Core 8 Output Caching)
  • Considerar separación del worker NINA a un proyecto independiente (ya existe NINA-WorkerService — consolidar)
  • Implementar API versioning para los controllers que tienen consumidores externos

4B · Performance avanzada

  • Implementar SQL Server Full-Text Search completo para búsqueda de glosario y directorio
  • Evaluar uso de Redis/IDistributedCache para caché de búsquedas compartida entre instancias
  • Implementar paginación cursor-based para historiales clínicos largos
  • Migrar notificaciones push de polling a WebSockets/SignalR
  • Añadir Limit de workers concurrentes para la queue "ai" de Hangfire

4C · Calidad de código

  • Añadir test coverage: al menos Services críticos (GlossaryService, NinaModelRouterService, BadgeService)
  • Integrar análisis estático (SonarQube o Roslyn analyzers) en el pipeline CI
  • Configurar dotnet list package --vulnerable como gate de CI
  • Documentar API con Swagger/OpenAPI para todos los controllers

4D · UX/Accesibilidad

  • Audit completo WCAG 2.1 AA con herramienta automática (axe, Lighthouse) + revisión manual
  • Implementar modo oscuro completo (prefers-color-scheme + toggle manual)
  • Completar PWA: manifest.json con todos los iconos, offline support para páginas clave
  • Open Graph + meta description dinámica para páginas del directorio médico
  • Migrar iconografía a una sola librería (eliminar la duplicación Bootstrap Icons / FontAwesome)

4E · Seguridad avanzada

  • Implementar rate limiting a nivel de middleware (ASP.NET Core 8 Rate Limiting built-in)
  • Revisar y documentar todos los endpoints públicos no autorizados (intencionales vs accidentales)
  • Implementar audit log de accesos a datos clínicos (¿quién accedió a qué y cuándo?)
  • Security headers: Content-Security-Policy, HSTS, X-Frame-Options
  • Rotar API keys de Anthropic, SendGrid y Twilio periódicamente
