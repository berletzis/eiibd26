⚠ UI-001 — 7 archivos CSS definen :root overlapping
Las custom properties CSS (--primary, --bg, --text, etc.) están redefinidas en 7 archivos distintos con valores diferentes. El comportamiento visual depende del orden de carga de los archivos, que puede cambiar entre páginas.

HIGH — Problemas estructurales de CSS/Layout

UI-001 HIGH 7 archivos CSS definen :root con custom properties solapadas

Se detectaron 7 archivos CSS que definen bloques :root { ... } con custom properties parcialmente solapadas. El navegador aplica el último valor cargado para cada propiedad, pero el orden de carga varía según la página, causando inconsistencias visuales entre vistas.

ArchivoPropiedades conflictivas
wwwroot/css/site.css--primary, --bg, --text, --border
wwwroot/css/dashboard.css--primary, --sidebar-bg, --text
wwwroot/css/directorio.css--primary, --card-bg, --border
wwwroot/css/glosario.css--bg, --text, --primary
wwwroot/css/medico.css--primary, --accent
wwwroot/css/admin.css--primary, --danger
wwwroot/css/perfil.css--primary, --bg
Impacto: colores y espaciados inconsistentes entre páginas Solución: centralizar todas las custom properties en site.css · eliminar :root duplicados
UI-002 HIGH _Layout.cshtml — brace imbalance sospechado en bloque JavaScript principal

El archivo _Layout.cshtml contiene un bloque <script> principal con JavaScript inline que tiene asimetría en llaves { } o paréntesis. Esto puede causar que funciones definidas después del error no se registren, afectando funcionalidad en toda la aplicación.

La sintaxis de Razor y JavaScript mezclada en el mismo archivo dificulta la detección de errores de brace balance con linters estándar.

Archivo: Pages/Shared/_Layout.cshtml Verificar con: browser DevTools → Console al cargar cualquier página
UI-003 HIGH Detalles.cshtml — 1963 líneas, god-file de UI

Pages/Directorio/Detalles.cshtml tiene 1963 líneas y combina: HTML de la vista, CSS inline con más de 200 líneas de estilos, JavaScript inline (tabs, lightbox, mapas), lógica de renderizado condicional compleja, y llamadas a helper methods.

Cambios en cualquier parte del perfil médico requieren navegar un archivo de 2K líneas. El riesgo de introducir regresiones es alto.

// Breakdown aproximado del archivo: // Líneas 1-50: @using, @model, @inject declaraciones // Líneas 51-300: CSS inline (<style> block) // Líneas 301-800: Header del perfil, badges, áreas EII // Líneas 801-1200: Tabs de contenido (historial, Q&A, laboratorios) // Líneas 1201-1600: Secciones condicionales (Medico vs Paciente) // Líneas 1601-1963: JavaScript inline (tabs, lightbox, analytics)
Archivo: Pages/Directorio/Detalles.cshtml · 1963 líneas Solución: extraer CSS a directorio.css · JS a directorio.js · partials para cada sección
UI-004 HIGH jQuery — doble carga: CDN en _Layout + versión local conflictiva

jQuery se carga dos veces en algunas páginas: una vez desde CDN en _Layout.cshtml y una segunda vez desde wwwroot/lib/jquery/ en algunos bundles o partial views. La doble carga reinicializa jQuery, deshaciendo los event handlers registrados antes de la segunda carga.

Los plugins de jQuery (jQuery Validate, Select2 si se usa) quedan en estado indefinido después de la segunda carga.

Archivos: Pages/Shared/_Layout.cshtml · wwwroot/lib/jquery/jquery.js Impacto: validación de formularios puede dejar de funcionar en páginas afectadas
UI-005 HIGH Sidebar menu — 3 versiones parcialmente duplicadas

Se identificaron 3 archivos que implementan variantes del menú lateral: _SidebarMenu.cshtml, _SidebarMenuMedico.cshtml y lógica inline de sidebar en algunas páginas de admin. Los tres tienen lógica de visibilidad de items por rol duplicada. Cambios en el menú requieren actualizar 3 archivos.

Pendiente documentado en CLAUDE.md: C-01 — agregar &&!IsInRole("Administrador") Este fix debe aplicarse en los 3 archivos si hay duplicación

MEDIUM — Inconsistencias y deuda técnica de UI

UI-006 MEDIUM Top-menu muestra email en lugar del nombre del médico

El menú superior muestra el email del usuario en lugar del nombre completo cuando el usuario es médico. Esto ocurre cuando Perfil.Nombre no está disponible en el contexto del partial view del top menu.

El fix pendiente (C-02 en CLAUDE.md) requiere inyectar ApplicationDbContext en _TopMenuDesktop.cshtml y _TopMenuMobile.cshtml y leer Perfil.Nombre.

Archivos: Pages/Shared/_TopMenuDesktop.cshtml · _TopMenuMobile.cshtml Documentado en CLAUDE.md: pendiente C-02
UI-007 MEDIUM CSS inline en múltiples Razor Pages — estilos no compartidos ni reutilizables

Al menos 12 páginas Razor tienen bloques <style> inline con reglas CSS específicas de esa página. Estos estilos no son reutilizables, no se benefician de caché del navegador, y pueden conflictuar con las custom properties de UI-001.

Areas/Identity/Pages/Medico/Dashboard.cshtml~80 líneas
Areas/Identity/Pages/Account/Manage/PerfilMedico.cshtml~60 líneas
Pages/Glosario/Index.cshtml~40 líneas
+ 8 páginas más con CSS inline menor
Total estimado: ~600 líneas de CSS inline que deberían estar en archivos .css
UI-008 MEDIUM JavaScript inline en Razor Pages — mezcla de Razor y JS dificulta mantenimiento

Al menos 8 páginas tienen bloques <script> inline con JavaScript que usa valores de C# interpolados con @Model.X. Esto mezcla idiomas, dificulta el linting de JS, impide el uso de bundling, y hace imposible escribir tests unitarios para el JavaScript.

// Patrón problemático (ejemplo de Detalles.cshtml): <script> const medicoId = @Model.MedicoId; // interpolación Razor en JS const areaIds = @Json.Serialize(Model.AreasEii); // objeto C# → JS // ... 200 líneas de JavaScript que dependen de valores del servidor </script>
Solución: data-attributes en HTML para pasar datos del servidor → JS externo
UI-009 MEDIUM Bootstrap 5 + CSS customizado — specificity wars en componentes

El CSS custom del proyecto sobreescribe componentes de Bootstrap 5 usando selectores de alta especificidad (ej: div.card.perfil-card .btn-primary) en lugar de variables CSS de Bootstrap o @include de Sass. Esto crea "specificity wars" que dificultan la previsibilidad de estilos.

Patrón detectado en: dashboard.css, directorio.css, perfil.css
UI-010 MEDIUM Imágenes sin atributo alt — accesibilidad y SEO afectados

Se detectaron imágenes en el directorio médico y en el glosario sin atributo alt o con alt="" en imágenes que no son decorativas. Esto viola las pautas WCAG 2.1 AA y afecta el posicionamiento SEO de las páginas públicas.

Afecta: SEO de directorio médico (páginas públicas indexadas por Google)
UI-011 MEDIUM Formularios sin validación client-side en campos requeridos

Varios formularios de registro de condiciones, síntomas y tratamientos no tienen validación client-side con jQuery Validate. Los usuarios reciben feedback solo tras el POST al servidor, degradando la experiencia de usuario.

Páginas afectadas: UsuarioCondiciones, UsuarioSintomas, UsuarioTratamientos
UI-012 MEDIUM Modal de confirmación — implementación inconsistente (Bootstrap modal vs alert() nativo)

Las confirmaciones de eliminación usan window.confirm() nativo en algunas páginas y Bootstrap modals en otras. El window.confirm() bloquea el thread JS y tiene aspecto diferente según el navegador.

Afecta: UX de eliminación de condiciones, síntomas, tratamientos
UI-013 MEDIUM Loading states ausentes en operaciones async (guardado de perfil, preguntas P&R)

Los formularios que requieren procesamiento server-side (guardado de perfil, envío de preguntas al sistema de P&R) no muestran estado de carga mientras esperan la respuesta. El botón permanece habilitado, permitiendo múltiple click/submit accidental.

Riesgo funcional: doble submit puede crear registros duplicados
UI-014 MEDIUM Responsive — layout roto en viewport 768px-1024px (tablet)

El diseño tiene breakpoints para mobile (<768px) y desktop (>1024px), pero el rango tablet (768px-1024px) presenta: sidebar superpuesto al contenido, tarjetas de médicos con overflow horizontal, y formularios de perfil con campos que se salen del viewport.

Detectado en: directorio, dashboard médico, perfil de médico
UI-015 MEDIUM Toast/flash messages — implementación duplicada en 3 archivos de layout

Los mensajes de éxito/error (flash messages) se implementan de forma diferente en el layout principal, el layout de área Identity, y el layout de área Admin. Tres versiones de la misma funcionalidad con diferentes estilos y comportamientos de auto-cierre.

UI-016 MEDIUM Paginación — implementación custom incompatible con Bootstrap 5 pagination component

Varias páginas implementan su propio componente de paginación con HTML custom en lugar de usar el componente de paginación de Bootstrap 5. Los componentes custom tienen estilos inconsistentes entre páginas y no respetan el tema CSS global.

UI-017 MEDIUM Iconografía — mezcla de Bootstrap Icons, FontAwesome y SVG inline

El proyecto usa simultáneamente Bootstrap Icons (via CDN), FontAwesome (via CDN separado) y SVG inline en algunas páginas. Tres librerías de iconos cargadas para la misma aplicación, con estilos y tamaños inconsistentes.

Impacto: +2 requests HTTP extra por página · ~150KB extra de iconos no usados
UI-018 MEDIUM Modo oscuro — variables CSS definidas pero toggle no implementado

Varias hojas de estilo tienen comentarios con variables para modo oscuro (/* dark mode */) pero no hay implementación del toggle ni media query prefers-color-scheme: dark. Las variables oscuras están definidas pero nunca se aplican.

UI-019 MEDIUM Gráficas de estado de ánimo — Chart.js cargado globalmente aunque solo se usa en 2 páginas

Chart.js (~200KB minificado) se carga en el layout global aunque solo se usa en 2 páginas (estado de ánimo y dashboard de insights). Esto añade 200KB al bundle inicial de cada página.

Solución: carga condicional de Chart.js solo en las páginas que lo usan
UI-020 MEDIUM Formulario de registro de médico — campos largos sin indicador de progreso

El formulario de registro médico (RegisterM.cshtml) es un formulario largo en una sola página sin indicador de progreso ni pasos. Los médicos pueden abandonar el registro a mitad sin saber cuánto falta.

UI-021 MEDIUM Árbol de laboratorios — UI de selección compleja sin búsqueda

La interfaz de selección de parámetros de laboratorio usa un árbol jerárquico con múltiples niveles pero sin campo de búsqueda. Encontrar un parámetro específico (ej: "Calprotectina fecal") requiere navegar manualmente por el árbol.

UI-022 MEDIUM Autocompletado de búsqueda — sin debounce o con debounce demasiado corto

El campo de búsqueda del directorio y del glosario dispara el autocompletado con cada keystroke (o con debounce <200ms). Cada keystroke genera los 16 queries documentados en PERF-001. Con debounce de 300-500ms se reduciría el 70% de las queries innecesarias.

Relacionado con: PERF-001, PERF-002, PERF-003
UI-023 MEDIUM Badges de médico — sin tooltip explicativo en el directorio

Los badges del directorio médico (verificado, especialista EII, etc.) se muestran como íconos sin tooltip ni descripción. Los usuarios no saben qué significa cada badge sin documentación externa.

UI-024 MEDIUM Selector de fecha de nacimiento — input date nativo sin validación de rango

El campo de fecha de nacimiento usa <input type="date"> sin atributos min/max. Un usuario puede ingresar fechas de nacimiento en el futuro o de hace 200 años sin validación client-side.

LOW — Accesibilidad y pulido visual

UI-025 LOW Links de navegación sin aria-current en menú activo

El menú lateral no aplica aria-current="page" al item activo. Los lectores de pantalla no pueden anunciar en qué sección se encuentra el usuario.

UI-026 LOW Contraste de color insuficiente en texto muted sobre fondo claro

Varios textos de ayuda y labels secundarios usan color: #999 sobre fondo blanco, con ratio de contraste ~2.5:1. WCAG 2.1 AA requiere mínimo 4.5:1 para texto normal.

Afecta: textos de ayuda en formularios, metadatos en tarjetas
UI-027 LOW Focus ring eliminado con outline:0 en botones

Algunos botones tienen outline: 0 o outline: none en su CSS, eliminando el indicador de focus del teclado. Usuarios de navegación por teclado no pueden ver qué elemento tiene foco.

UI-028 LOW Formularios — labels no asociados con for/id en algunos campos

Algunos campos de formulario tienen el label separado del input sin atributo for que referencie el id del input. Los lectores de pantalla no pueden anunciar el label al enfocar el input.

UI-029 LOW Meta description vacía en páginas públicas del directorio

Las páginas de perfil de médico en el directorio no tienen <meta name="description"> único generado dinámicamente. Google usa el texto de la página como snippet, que puede quedar truncado o irrelevante.

Impacto: SEO de páginas de perfil médico
UI-030 LOW Open Graph tags ausentes en páginas del directorio

Las páginas del directorio médico no tienen tags og:title, og:description, og:image. Compartir el perfil de un médico en redes sociales no genera preview enriquecido.

UI-031 LOW Print stylesheet ausente — PDF de perfil médico vía browser imprime mal

No hay @media print stylesheet. Si un usuario imprime la página del directorio desde el navegador, el sidebar, el header y los menús se imprimen junto al contenido relevante.

UI-032 LOW Favicon y manifest.json no optimizados para PWA

El proyecto incluye un service worker y push notifications (infraestructura PWA), pero el manifest.json puede tener iconos faltantes para los tamaños de pantalla requeridos por iOS y Android.

UI-033 LOW CSS vendor prefixes obsoletos en archivos del proyecto

Se detectaron vendor prefixes obsoletos (-webkit-, -moz-) en propiedades CSS que son estándar desde hace años (border-radius, transition, flexbox). Añaden ruido sin beneficio en browsers modernos.

UI-034 LOW Error 404 y 500 — páginas de error sin diseño personalizado

Las páginas de error 404 y 500 usan el diseño por defecto de ASP.NET Core. No tienen navegación ni contexto de la plataforma, presentando una experiencia de usuario deficiente en casos de error.

UI-035 LOW Textos hardcodeados en español — sin soporte para internacionalización

Todos los textos de la interfaz están hardcodeados en español directamente en las vistas. No se usa el sistema de recursos (.resx) de ASP.NET Core. Si en el futuro se necesita traducción, requeriría modificar todas las vistas.

Nota: aceptable para el MVP actual, pero documenta la deuda técnica
UI-036 LOW Spinner de carga global — ausente en navegaciones lentas

No hay indicador global de carga durante navegación entre páginas. En conexiones lentas o respuestas lentas del servidor, el usuario ve la página anterior sin ningún feedback visual de que algo está cargando.

UI-037 LOW Textarea de síntomas/notas — sin contador de caracteres

Los campos de texto libre para notas de síntomas y tratamientos tienen maxlength definido en el modelo pero sin contador visual en la UI. Los usuarios llegan al límite abruptamente sin previo aviso.

UI-038 LOW Scroll to top — ausente en páginas largas (Detalles, Dashboard)

Las páginas largas (perfil de médico de 1963 líneas renderizadas, dashboard) no tienen botón de "volver arriba". En mobile, el usuario debe hacer scroll manual hasta el tope.
