HIGH — Versiones críticas desalineadas

DEP-001 HIGH DataProtection.Extensions 10.0.3 — apunta a .NET 10 en proyecto .NET 8

Microsoft.AspNetCore.DataProtection.Extensions versión 10.0.3 es el paquete de .NET 10. El proyecto tiene <TargetFramework>net8.0</TargetFramework>. Esta desalineación puede causar:

  • Binarios de .NET 10 cargados en runtime de .NET 8 — comportamiento indefinido
  • APIs de DataProtection de .NET 10 usadas inadvertidamente que no existen en .NET 8
  • Advertencias de compatibilidad en publish que podrían ocultarse
<!-- eiibd26.csproj — versión problemática: --> <PackageReference Include="Microsoft.AspNetCore.DataProtection.Extensions" Version="10.0.3" /> <!-- Versión correcta para .NET 8: --> <PackageReference Include="Microsoft.AspNetCore.DataProtection.Extensions" Version="8.0.x" />
Archivo: eiibd26/eiibd26.csproj Acción: verificar si se usa explícitamente, downgrade a 8.x si es necesario
DEP-002 HIGH CodeGeneration.Design 9.0.0 — herramienta de scaffolding .NET 9 en proyecto .NET 8

Microsoft.VisualStudio.Web.CodeGeneration.Design 9.0.0 corresponde a .NET 9. Este paquete es para scaffolding de controladores y vistas en tiempo de desarrollo.

Riesgos:

  • Conflicto de versiones con Microsoft.EntityFrameworkCore.Design que está en 8.0.21
  • El paquete de desarrollo no debería estar en .csproj en producción — añade dependencias no necesarias en el build de producción
  • Puede causar advertencias o errores en dotnet publish
Acción: verificar si se usa activamente para scaffolding · considerar mover a DevDependency

MEDIUM — Paquetes con riesgo de soporte o actualización pendiente

DEP-003 MEDIUM WebPush-NetCore 1.0.2 — sin actualizaciones desde 2017

WebPush-NetCore versión 1.0.2 no ha tenido actualizaciones desde 2017. La especificación de Web Push y VAPID ha evolucionado desde entonces. Riesgos:

  • El paquete puede usar APIs de criptografía obsoletas o inseguras para firmar las notificaciones VAPID
  • Sin soporte activo para vulnerabilidades futuras
  • La implementación de VAPID del paquete puede ser incompatible con versiones futuras de Chrome/Firefox

Alternativa recomendada: Lib.Net.Http.WebPush que tiene mantenimiento activo y soporte de .NET 8.

Último commit del repositorio: ~2017 Impacto: notificaciones push pueden dejar de funcionar en browsers futuros
DEP-004 MEDIUM Hangfire 1.8.23 — versión mayor anterior disponible (Hangfire Pro)

Hangfire 1.8.23 es una versión estable de la rama OSS. Sin embargo, la rama 1.8.x puede quedar en mantenimiento de seguridad únicamente si Hangfire lanza 2.0. Considerar:

  • Verificar que Hangfire.SqlServer y Hangfire.Core están en la misma versión (1.8.23)
  • Confirmar que el schema de Hangfire en BD es compatible con la versión usada
Paquetes: Hangfire.Core, Hangfire.SqlServer, Hangfire.AspNetCore Riesgo: bajo si los tres están alineados en la misma versión
DEP-005 MEDIUM Markdig 1.1.1 — versión muy antigua (última: 0.38+)

Markdig tiene versioning poco intuitivo: 1.1.1 en NuGet corresponde a una versión moderna, pero vale la pena verificar que es la versión correcta y que está siendo mantenida activamente. Markdig tiene releases frecuentes con fixes de seguridad para parseo de Markdown.

La versión usada puede tener vulnerabilidades de XSS si el Markdown renderizado incluye input del usuario sin sanitización adicional.

Riesgo XSS: si el Markdown de artículos del glosario puede ser editado por usuarios no-admin
DEP-006 MEDIUM LigerShark.WebOptimizer 3.0.477 — integración no verificada en producción

WebOptimizer está incluido en el proyecto (3.0.477) para bundling y minificación, pero no se puede confirmar si está activo en producción. Si no está configurado correctamente, los archivos JS/CSS se sirven sin minificar, y los archivos múltiples no se combinan.

Si está configurado en modo Development únicamente (lo que es un error común), producción recibe archivos no optimizados.

Verificar: Program.cs → app.UseWebOptimizer() y configuración en Startup
DEP-007 MEDIUM Twilio 7.13.8 — SDK con actualizaciones de seguridad frecuentes

El SDK de Twilio (7.13.8) tiene actualizaciones frecuentes, algunas con correcciones de seguridad. Twilio también puede deprecar versiones antiguas del SDK cuando cambia su API REST. Se recomienda verificar si hay vulnerabilidades conocidas en esta versión.

Última versión disponible en NuGet: 7.x.x+ Acción: ejecutar dotnet list package --vulnerable para verificar CVEs

LOW — Observaciones y actualizaciones recomendadas

DEP-008 LOW QuestPDF 2024.10.4 — versión anterior disponible (2025.x)

QuestPDF 2024.10.4 es una versión estable pero puede tener versiones más recientes con mejoras de rendimiento en generación de PDF. QuestPDF tiene licencia libre para aplicaciones de uso interno/revenue < $1M USD anual. Confirmar que la licencia aplica al caso de uso de EIIBD.

Licencia: Community (gratuita con limitaciones)
DEP-009 LOW SixLabors.ImageSharp 3.1.12 — licencia Six Labors Split License

ImageSharp 3.1.12 usa la "Six Labors Split License": gratis para proyectos de código abierto y aplicaciones de bajo uso comercial, pero requiere licencia comercial para proyectos cerrados con cierto nivel de uso. Verificar que la licencia aplica correctamente al contexto de EIIBD.

Acción: revisar Six Labors Split License para confirmar elegibilidad
DEP-010 LOW SendGrid 9.29.3 — versión reciente, sin issues conocidos

SendGrid 9.29.3 es una versión relativamente reciente del SDK oficial de Twilio SendGrid. Sin issues críticos conocidos. La API key de SendGrid debe rotar periódicamente y tener permisos mínimos necesarios (solo envío, sin acceso a contactos si no se usa).

Estado: OK · Recomendación: verificar permisos de la API key
DEP-011 LOW EF Core 8.0.21 — alineado, pero no en la última versión patch de .NET 8

Todos los paquetes de EF Core están en 8.0.21, que es coherente internamente. Sin embargo, Microsoft puede haber lanzado patches de seguridad o fixes de bugs en 8.0.x posterior. Verificar si 8.0.21 es el último disponible de la rama 8.x.

Paquetes EF Core alineados: EntityFrameworkCore, EF.SqlServer, EF.Tools, EF.Design Estado: consistente internamente ✓
DEP-012 LOW Anthropic SDK — versión y origen no verificados en este audit

No se encontró un paquete oficial de Anthropic en NuGet en el proyecto. La integración con la API de Claude puede estar usando HttpClient directamente o un wrapper custom. Si es custom, verificar que maneja correctamente: rate limiting, retry exponential backoff, token counting y timeout.

Verificar: Services/AI/ para el cliente HTTP de Anthropic
DEP-013 LOW Sin análisis de vulnerabilidades en pipeline CI

No se evidencia un paso de dotnet list package --vulnerable ni dotnet audit en el pipeline CI/CD. Las vulnerabilidades en dependencias NuGet pueden pasar desapercibidas hasta que se ejecuta manualmente.

Acción: agregar dotnet list package --vulnerable al pipeline de CI
